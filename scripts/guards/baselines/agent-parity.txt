# Parity-gap ledger for scripts/guards/agent-parity.mjs.
#
# Each line is an /api path the web client calls that no flue tool reaches. The
# guard fails on any gap NOT listed here, so this file is the boundary between
# "known debt" and "new regression". It is a ledger, not an exemption list —
# when a tool is written, delete its line (the guard reports stale entries).
#
# Two kinds of entry live here, marked accordingly:
#   [gui-only]  legitimately not an agent capability — browser plumbing.
#   [gap]       a real parity gap; the agent should be able to do this.

# --- [gui-only] browser plumbing, transport, and session ---------------------
/api/upload                       # multipart body from a file input; the agent attaches by URL
/api/sounds/upload                # multipart body from a file input; the agent generates + attach_sound instead
/api/data/events                  # SSE subscription — a stream, not an operation
/api/script/events                # SSE subscription
/api/timeline/events              # SSE subscription
/api/projects                     # project switching is a client concern; the agent is scoped to one
# The three Director paths that are browser work by nature, not by omission. An
# agent has no peer connection, no decoded video and no muxer — and each of these
# is the browser doing the one thing it is uniquely able to do.
/api/stage/fal/proxy              # the WebRTC session itself; only a browser can hold one
/api/shotsheet/pins               # frames cut off the decoded take on screen; the agent pins via /api/director/series/*/pin
/api/musicalized/scored           # the mix, muxed in the browser so the picture is copied rather than re-encoded

/api/projects/*
/api/projects/*/activate
/api/nav/events                   # SSE subscription (agent → UI navigate commands)
/api/appstate                     # the client REPORTS its screen here; the agent reads the
                                  # hydrated view at /api/appstate/screen via view_screen,
                                  # so this write endpoint is correctly one-directional
/api/chat-title                   # derives a title for the chat rail from the first message
/api/chats                        # the per-user chat REGISTRY the clients sync history through —
                                  # the agent IS a chat; it has no business listing or deleting them
/api/transcribe                   # microphone capture → text, for the composer's dictation button
/api/history/*/*/restore          # the agent reaches this through restore_version, which posts a different literal
/api/auth/oauth2/link             # interactive browser OAuth (link Higgsfield to the Google session);
                                  # the agent gets the resulting token via the worker token bridge
/api/share/script/*               # the PUBLIC share-link viewer page (/share/script/<token>); the
                                  # agent manages links via share_script and never plays the viewer
/api/share/*                      # the PUBLIC share manifest (which tabs a link exposes), read by the
                                  # unified /share/<token> viewer page; the agent manages links via
                                  # share_script / share_world and never plays the viewer
/api/share/world/*                # the PUBLIC shared-world viewer payload (/share/<token>?tab=world);
                                  # same viewer-only plumbing as the shared-script route above

# --- [gui-only] moodboard canvas transport -----------------------------------
# The Moodboard's agent capability is /api/moodboard/cards (add_moodboard_card,
# remove_moodboard_card), which takes intent and does the placing, fetching and
# unfurling itself. These four are the CANVAS's transport: they carry live
# geometry (cursor position, measured image size, the free cell under the
# pointer) that only a pointer on a rendered canvas has, and handing the model a
# coordinate space to invent would just pile cards on top of each other.
/api/moodboard/ops                # optimistic op stream; needs live drag/resize geometry
/api/moodboard/image              # raw bytes from a dropped File / clipboard Blob
/api/moodboard/video-from-url     # the card route fetches + stores video itself
# (/api/moodboard/unfurl needs no entry: the client builds it as a template
#  literal with a query string, which the guard's path regex doesn't collect.)

# --- [gui-only] series / episode management + character roster ---------------
# The agent's series capabilities are set_format, list_episodes and
# create_episode (flue-agent/src/tools/). The paths below are browser-side:
# switching/renaming/deleting an episode is a header action that rebinds the open
# conversation (the agent can't re-scope its own chat), and the roster picker +
# anchor toggle are World-tab affordances the agent reaches through save_world /
# add_world_character (both accept the roster and the `anchor` flag).
/api/episodes/*                   # rename/delete an episode — header management UI
/api/episodes/*/activate          # switching episode rebinds the chat; a client action
/api/episode/roster               # "add previous character" picker; agent uses save_world
/api/world/character/*/anchor     # anchor toggle; agent sets `anchor` via save_world
/api/world/characters/library     # the roster picker's library list; agent has get_world

# --- [gui-only] teams: the accept flow + management transport ----------------
# Team CAPABILITIES the agent has: list_orgs, list_members, invite_member,
# set_member_scope, remove_member (see flue-agent/src/tools/). The paths below
# are the browser-side of teams that the agent legitimately doesn't drive.
/api/orgs/*/projects              # the invite scope-PICKER enumerates an org's projects; the
                                  # agent already has project ids from its own context / list_orgs
/api/orgs/*/invitations/*/revoke  # un-inviting is a manager click in the members UI
/api/orgs/invitations/*/accept    # a human accepts their own invite in the browser while signed in —
                                  # not an agent operation (the agent isn't the invitee)

# --- [gui-only] musical: the audio upload + a manual reset -------------------
